# Decisions and observed failures

## KITTI continuation after goal clarification

- The user specified four objectives: deep learning plus geometric positioning, continuous-input system engineering, Jetson/TensorRT migration, and reproducible correctness/performance evidence. Only public data are available. The new primary validation path is KITTI RGB stereo; thermal calibration no longer blocks that independent path.
- Official KITTI web pages require login, but the publicly served official download script and its object-store URLs are anonymously accessible. Read-only HEAD requests returned HTTP 200; the selected sequence, calibration and tracklets total about 646 MB. No credentials or private mirror were used.
- StereoSGBM estimates depth from the left/right images. LiDAR and tracklets are loaded only for offline reference work and never enter `process_kitti_images`. Full P matrix translation terms are preserved; tracklet poses are in Velodyne coordinates with bottom-center origins.
- A bounding-box median represents visible surface points, not a three-dimensional box center. Evaluation therefore compares stereo and LiDAR at common projected pixels, with a separate subset supported by matched tracklet volumes. No object-center precision or official detection mAP is claimed.
- A 10 Hz replay completed all 154 groups. A deliberate 30 Hz overload run tested skipping stale input indices with no decoded-image backlog; all skipped indices were recorded. Source timestamps remain unchanged and are separate from the replay schedule.
- The first paced run processed frames but failed while serializing a NumPy integer deadline counter. Preserved traceback in `kitti_failure_serialization.log`; converted only the aggregate count to a built-in int. Re-ran the original 154-frame command successfully. No latency thresholds were changed.
- The unpaced, 10 Hz and offline evaluation outputs have the same content digest. No dependency was added. See `kitti_status.md` for measured errors, timing and remaining scope.

## Earlier TartanRGBT work

- The workspace was empty. Created a small procedural Python package; preserved the supplied kit under `docs/execution-kit/`. The user requested implementation plus video, so its individual "paste Phase 0 only" prompt was not treated as the current request.
- Default `python` was Inkscape's bundled interpreter without pip; sandbox network lookup failed and that interpreter also lacked a usable HTTPS certificate chain. Used the existing normal Python 3.12.10 installation and project-local `.venv`; TLS verification remained enabled. No system Python or drivers were changed.
- Selected the smallest complete trajectory from the official file manifest. Required payload 889,043,374 bytes, plus small calibration/configuration files. Download pinned to repository commit. Hugging Face cache/resumption and ZIP CRC checks used; local SHA-256 hashes recorded.
- The first synthetic test run failed on a Python list passed as timestamp errors (`TypeError: '>=' not supported between instances of 'list' and 'int'`). Reproduced in `test_timestamp_pairing_checks_sidecars`; normalized timestamp arguments to NumPy arrays, then the same test and complete suite passed. No matching tolerance was loosened.
- The exact official released RGB intrinsics were kept. `configs/handheld.yaml` resolves TF semantics: child pose in parent. RGB-to-thermal point mapping therefore uses its inverse.
- The thermal extraction config selects `/thermal_left/image_processed`, while the calibration lists raw equidistant distortion and a projection matrix. Neither the checked dataset nor the official AnyThermal tree provides decisive image_processed-to-P provenance. Kept thermal 3D mapping blocked; no double distortion, identity substitute or fitted alignment.
- Source depth has enormous positive and negative values. Numerical validity means finite positive Z only; it is not a physical-accuracy assertion. The audit retains extrema, and display-only range/crop limits are labeled. Box geometry uses a visible componentwise-median policy with valid counts and MAD.
- All 296 valid groups were run through YOLOX Nano. Twenty raw predictions occurred, including three person predictions and obvious metal-gate/train false positives. Did not hide or relabel them. An official dog image validated preprocessing independently; it does not establish mAP.
- The nominal 10 Hz release has variable source intervals. Replay uses actual timestamps. Video quantizes them onto a 10 fps presentation clock and holds the prior image for gaps. FFC groups are excluded rather than filled with invented measurements.
- The measured unpaced CPU baseline already exceeds the reduced pipeline's processing target. No optimization or speedup claim was invented. Paced and render runs have separate metrics.
- No Jetson access exists. Prepared a standard-library read-only probe and instructions; no SSH or device changes were attempted. Optional MID 3K evaluation and tracking were not enabled.
- Video is an H.264 MP4 below the 10 MB free-plan attachment threshold documented by GitHub. Git excludes data, weights and video renders. Local repository initialized, with no commit, remote or push.
