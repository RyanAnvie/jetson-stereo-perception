# KITTI 阶段验收记录

本轮已完成公开数据驱动的 PC 基线：**YOLOX Nano 检测 → 标定双目深度 → 相机坐标系中的三维表面代表位置 → 独立 LiDAR 参考检查**。这是向深度学习感知和连续系统工程的扩展。Jetson/TensorRT 部署尚未验收。

## 实现与数据

- 使用官方公开 KITTI raw 序列 `2011_09_26_drive_0005_sync`，154 组左右图像、原始时间戳、标定、LiDAR 和 15 条 tracklets。三个压缩包合计 646,299,418 字节；来源、大小和 SHA-256 见 [下载记录](kitti_download_manifest.json)。
- 检测和三维位置计算只使用左右 RGB 与公开标定；LiDAR 和标签仅用于离线评估。输出保留原始纳秒时间戳。
- 坐标为 `kitti_cam2_rect`，X 向右、Y 向下、Z 向前，单位米。保留投影矩阵第四列的所有平移项。位置定义为检测框内有效双目点的逐分量中位数，不能解释为物体中心。
- 双目时间差 p95 为 0.615 ms，154 组均满足配置中明确给出的 5 ms 容差。原始输入平均约 9.684 Hz，受控 10 Hz 回放使用独立调度时钟。
- 新增数据下载、标定/tracklet 解析、StereoSGBM、离线误差计算、连续回放、逐帧 JSONL/CSV 输出和视频。没有新增 Python 依赖、装饰器或类。

## 已执行的性能检查

Windows 11、Python 3.12.10、CPU FP32、ONNX Runtime 与 OpenCV 各 4 线程。原始图像 1242×375，检测网络输入 416×416。每次正式计时前预热 5 帧，再完整执行所选序列。机器上的 NVIDIA GPU 未用于这些结果。

| 检查 | 实际结果 |
| --- | --- |
| 无界面基线 | 154 帧；14.14 FPS；处理延迟 p95 59.34 ms |
| 受控 10 Hz 输入 | 154 帧完成，0 帧丢弃；调度输入至输出延迟 p95 74.18 ms；没有超过 100 ms 的帧 |
| 受控 30 Hz 过载 | 154 帧输入，83 帧完成、71 帧显式丢弃；完成吞吐 16.06 FPS；调度输入至输出 p95 95.31 ms，3 帧超过 100 ms |
| 输出一致性 | 无界面、10 Hz、离线评估的 154 帧预测内容摘要一致 |
| 检测与位置 | 992 次跨帧检测输出，976 次有有效三维位置；不是不同物体数量 |

30 Hz 检查验证的是过载时跳过旧帧并记录索引的行为，不能宣称系统达到 30 FPS。当前循环串行处理一帧，没有积压的解码帧队列；这仍是离线数据按时钟回放，尚未连接真实传感器。性能是短序列单次运行观测，不是长时间实时性保证。分阶段数据和测量定义见 [比较表](kitti_comparison.md) 与 [复现说明](../docs/KITTI.md)。

## 已执行的误差检查

| 参考范围 | 共同有效像素数 | 深度 MAE | 深度 RMSE | 绝对误差中位数 |
| --- | ---: | ---: | ---: | ---: |
| 全部投影 LiDAR 共同像素 | 2,322,696 | 1.857 m | 12.227 m | 0.231 m |
| 匹配目标表面共同像素 | 97,334 | 0.955 m | 2.938 m | 0.355 m |

全部 LiDAR 投影像素中的有效双目覆盖率为 76.98%。259 次符合评估筛选条件的标签实例中，216 次与检测配对；该数量不是官方检测召回率。匹配条件、遮挡/截断筛选及像素选择均明确记录，没有为了降低误差而删除大误差样本。RMSE 显著高于中位误差，说明仍有严重失败样本，尤其需要继续分析深度边缘和远距离目标。

这些是双目深度相对原始 LiDAR 的差异。LiDAR 扫描约跨越 103 ms、与相机时间戳相差约 10.5 ms，当前未做运动补偿；标定、遮挡和像素取整也会影响差异。目标子集使用真实框离线选择参考像素，不能把其误差当成运行时完整检测框中位位置的误差，更不能当成物体中心精度。完整统计见 [评估报告](kitti_evaluation.json) 与 [逐帧及逐目标记录](kitti_evaluation_errors.json)。

## 测试与视频交付

- 工作环境和独立新建环境均实际执行 **21 项测试并通过**，日志为 [工作环境](kitti_tests.log) 和 [独立环境](kitti_fresh_tests.log)。新增测试覆盖完整投影项、纳秒时间戳、LiDAR 最近深度与索引保留、tracklet 底面中心、类别匹配、异常误差保留、已知视差的合成纹理，以及过载调度。
- 首次 10 Hz 运行在报告写出时遇到 NumPy 整数无法 JSON 序列化，已将计数明确转为 Python `int` 并重新执行完整 154 帧。保留 [失败日志](kitti_failure_serialization.log)，不将该失败运行作为验收证据。
- 视频：`results/kitti/axg_kitti_3d_demo.mp4`，23.9 秒、1280×800、10 fps、H.264/yuv420p，3,214,356 字节。包含真实检测、双目深度、XYZ 表、参考检查和来源说明。精确参数见 [视频元数据](kitti_video_metadata.json)。
- 视频适合按 [交付说明](../docs/VIDEO.md) 上传为 GitHub 附件；当前没有提交、推送或上传。原始数据、权重和视频保留在被 Git 忽略的目录。
- 最终语法、编码规范、预测摘要、逐帧记录数量、视频完整解码及文件大小检查见 [发布检查记录](kitti_release_validation.json)。

## 尚未完成的目标

Jetson 硬件上的运行、TensorRT 数值一致性及速度/功耗对比尚未执行；不能据此声明边缘部署完成。当前 CPU 开销主要来自双目匹配，单独转换检测器不代表整体系统会获得同等加速。跨序列泛化、长时间运行、真实传感器输入、运动补偿参考和物体中心定位仍需独立验证。热像标定关联保留为此前 TartanRGBT 分支的扩展问题。
